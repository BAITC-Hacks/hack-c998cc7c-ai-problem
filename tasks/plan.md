# Исправления и запуск Хаттама AI

## Объём

Исправить нарушения проверки черновика, валидации LLM и состояния редактора;
улучшить рабочий интерфейс; проверить реальный запуск и попробовать Cloudflare.
Существующий стек FastAPI/SQLite/vanilla JS сохраняется.

## Последовательность

1. Воспроизводимое Python-окружение и регрессионные тесты найденных ошибок.
2. Серверные правила проверки документа, доказательства LLM, накопление результатов,
   защита устаревшего повторного анализа; облегчённая выборка реестра поручений.
3. Согласованное состояние редактора и сохранения; адаптивный интерфейс со статусами,
   поиском, понятным сравнением результатов, сообщениями о загрузке и ошибках.
4. Защищённый внешний доступ, настройки доверенных хостов и ограничения загрузки;
   воспроизводимый запуск через Cloudflare Tunnel. Контейнер и отдельный сервер —
   следующий этап после выбора постоянного хостинга.
5. Backend/браузерные проверки, реальный пробный запуск, документация результата.

## Дизайн

Сохраняем тёмно-синий и бирюзовый бренд, системный шрифт с кириллицей.
Главная задача списка — найти запись и начать проверку; главное действие — загрузить запись.
Редактор — аудио/источник слева и результат справа, ясный прогресс проверки и сохранения.
На телефоне одна колонка, элементы управления не меньше 44 px, без горизонтального скролла
страницы; таблицы имеют собственную прокрутку. Состояния: пусто, загрузка, ошибка,
обработка, несохранённые правки, сохранение, конфликт ревизий, готовность к утверждению.

## Развёртывание

Текущий ASR требует native Python/FFmpeg и локальной модели. Прямой перенос этого процесса
в Workers не планируется. Первый пробный вариант — FastAPI за Cloudflare Tunnel,
с обязательной защитой доступа при публичном запуске. Постоянный вариант зависит от
выбора пользователя и доступного сервера. Supabase имеет смысл при необходимости
многопользовательской авторизации, Postgres и общего хранилища; для локального демо
сам по себе не нужен и не заменяет ASR-сервер.

## Проверка

Регрессии сначала должны воспроизвести ошибки; затем pytest и JS checks.
Браузер: редактирование/проверка/сохранение/утверждение, переключение страниц,
медленное сохранение, поиск, адаптивность 320/768/1024/1440, отсутствие ошибок JS.
Внешний запуск: доступ без авторизации закрыт, разрешённый вход работает,
health, API и статика доступны после входа. Результаты и ограничения записать в VALIDATION.md.
