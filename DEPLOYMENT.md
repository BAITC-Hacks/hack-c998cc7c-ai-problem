# Пробный запуск через Cloudflare

Приложение работает на этом компьютере: Python, faster-whisper, FFmpeg, SQLite и записи.
Cloudflare Tunnel предоставляет HTTPS-адрес. Это временное демо, а не постоянный хостинг:
после остановки процессов или выключения компьютера адрес перестаёт работать.
При новом запуске адрес и пароль меняются.

## Windows

1. Установите зависимости в `.venv` и модель `small` по README.
2. Скачайте `cloudflared-windows-amd64.exe` из
   [официальных релизов](https://github.com/cloudflare/cloudflared/releases),
   сверьте SHA256 с digest релиза и сохраните как `.cache/bin/cloudflared.exe`.
3. Выполните из корня проекта:

   ```powershell
   .venv/Scripts/python.exe scripts/start_demo.py
   ```

Скрипт запускает сервер на `127.0.0.1:8000`, проверяет готовность, создаёт Tunnel и
случайный пароль. Адрес, логин и пароль записываются в `.cache/demo/access.json`.
Этот файл исключён из git. Передавайте пароль только участникам демо.
Браузер попросит логин и пароль стандартным окном HTTP Basic Authentication.
Закрытие терминала не останавливает фоновые процессы.

Остановка:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop_demo.ps1
```

Логи находятся в `.cache/demo/app.log` и `.cache/demo/tunnel.log`.
Данные сохраняются в `data/` (либо в заданном `DATA_DIR`). Вход общий для всех участников:
они видят и редактируют одни и те же записи. Браузер может помнить Basic Auth до закрытия.
Не запускайте второй worker над этой SQLite-базой.

## Что настроено

- В публичном режиме приложение не стартует без пароля длиной минимум 16 символов
  и явного списка допустимых хостов. Скрипт создаёт пароль из 32 случайных байтов.
- HTTPS-перенаправление выполняется до запроса пароля. Uvicorn принимает proxy headers
  от loopback, через который подключается cloudflared.
- Интерфейс, записи, экспорты и API требуют авторизации; `/healthz` сообщает только `ok`.
- Лимит записи в демо — 90 MB. API отключает кеширование; служебные файлы frontend не публикуются.
- Режим LOCAL требует отдельного локального LLM. Без LLM выбирайте **RULES** при загрузке.
  Модель распознавания `small` установлена; endpoint внешнего LLM не настроен.

Quick Tunnel не имеет SLA и рассчитан на тестирование: см.
[ограничения Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).
Cloudflare находится на пути HTTPS-трафика; локальное распознавание не означает, что
при публичном доступе записи передаются только внутри компьютера.

## Постоянное размещение и Supabase

Для постоянного адреса потребуется работающий сервер с persistent disk, установленной моделью,
именованный Tunnel в вашем Cloudflare-аккаунте, домен и управление процессом как службой.
Для постоянного внешнего доступа используйте Cloudflare Access и ограничение запросов на edge.
Текущее ограничение неверных попыток входа действует в одном процессе и не заменяет edge-защиту.
Нужны резервные копии SQLite и каталога uploads, квоты диска и политика удаления записей.

Supabase пока не подключён: для одного общего демо SQLite достаточно. Supabase имеет смысл
для отдельных аккаунтов, Postgres и объектного хранилища. Это отдельная миграция с проверкой
доступа к каждой записи и RLS; она не заменяет Python-сервер распознавания.
Постоянный сервер, Cloudflare-аккаунт и домен в этой сессии не настраивались.
