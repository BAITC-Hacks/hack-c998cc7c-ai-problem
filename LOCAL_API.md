# Локальное приложение с ИИ через API

Интерфейс доступен только на `http://127.0.0.1:8000`. SQLite, записи и документы
хранятся на компьютере. Cloudflare Tunnel остановлен; Supabase не нужен.
Аудио передаётся провайдеру распознавания, а полученный текст — провайдеру анализа.
Это локальное приложение с внешней обработкой, а не полностью офлайн-система.

## Подключение провайдера

Файл `backend/.env` уже создан и исключён из Git. Заполните:

```dotenv
DEFAULT_MODE=HYBRID
DEFAULT_ASR_MODE=API
ASR_API_URL=https://YOUR-SPEECH-PROVIDER/v1
ASR_API_MODEL=YOUR-TIMESTAMPED-SPEECH-MODEL
ASR_API_KEY=
LLM_HYBRID_URL=https://YOUR-TEXT-PROVIDER/v1
LLM_HYBRID_MODEL=YOUR-TEXT-MODEL
LLM_API_KEY=
HOST=127.0.0.1
PUBLIC_MODE=false
```

Адреса и модели выше — обозначения, а не рабочие настройки. Укажите значения из кабинета
вашего провайдера. Если провайдер и ключ общие, заполните оба набора одинаковыми значениями.
Ключи читаются только Python-сервером; браузер их не получает.

Требования к API:

- Распознавание: `POST {ASR_API_URL}/audio/transcriptions`, Bearer-ключ, multipart WAV,
  `model`, `response_format=verbose_json`, `timestamp_granularities[]=segment`.
  Ответ должен содержать `segments` с `start`, `end`, `text`.
- Анализ: `POST {LLM_HYBRID_URL}/chat/completions`, Bearer-ключ, `messages`,
  `temperature=0`, `max_tokens=10000`; текст JSON в `choices[0].message.content`.
  Модель должна поддерживать эти параметры и достаточный размер ответа.
- Оба адреса требуют HTTPS. Не дописывайте пути `/audio/transcriptions` и
  `/chat/completions` в переменные URL — приложение добавляет их само.

Аудио-контракт соответствует формату
[OpenAI-compatible transcription](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create).
Совместимость текстового API сама по себе не означает поддержку аудио. Если ваш провайдер
не возвращает сегменты с временными метками, потребуется другой аудио-провайдер или адаптер.
Приложение не придумывает временные метки из обычного текстового ответа.

## Запуск

После изменения `.env` перезапустите сервер. На Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run.ps1
```

Запущенный в этой сессии фоновый сервер можно остановить командой
`powershell -ExecutionPolicy Bypass -File scripts/stop_local.ps1`, затем запустить
`scripts/run.ps1` заново. Сервер в обычном терминале останавливается через Ctrl+C.

На Linux: `bash scripts/run.sh`. Оба скрипта привязывают сервер к loopback.
Не запускайте второй экземпляр, пока первый занимает порт 8000.

Во вкладке «Настройки» проверьте два блока API. «Настроено» означает корректно заполненные
поля, а не подтверждённую доступность сервиса. В форме загрузки выберите API для аудио
и HYBRID для текста, укажите дату встречи и подтвердите обе передачи данных.
Начните с короткой разрешённой записи. Стоимость определяет ваш провайдер.

Для офлайн-варианта выберите локальный faster-whisper и RULES либо LOCAL.
При использовании аудио-API локальную Whisper-модель скачивать не нужно.
FFmpeg всё равно нужен для подготовки записи; используется установленный bundled FFmpeg.

## Ограничения и восстановление

Аудио нормализуется в mono PCM 16 kHz и отправляется частями до 600 секунд (~19.2 MB).
`ASR_CHUNK_SECONDS` можно уменьшить до лимита провайдера. Граница части может приходиться
на середину реплики; качество следует проверить на реальных записях.
Временные метки каждой части пересчитываются относительно начала всей встречи.
Говорящие пока размечаются вручную.

При ошибке распознавания нет автоматического перехода к локальной модели.
Повтор обработки после сбоя ASR заново отправляет аудио, что может повторно расходовать квоту.
После успешного распознавания транскрипт сохраняется как checkpoint: повторный анализ
текста не требует повторной отправки аудио. Старые встречи сохраняют свой исходный режим;
отсутствующий в старых данных `asr_mode` означает локальное распознавание.

Реальные запросы пока не проверены: провайдер, модели и ключи ещё не заданы.
