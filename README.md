# Хаттама AI — система автопротоколирования совещаний с фиксацией поручений

> Трек «AI-Problem» · Владелец задачи: **Самрук-Казына** · Хакатон BAITC-Hacks
>
> ИИ-ассистент, который по аудиозаписи совещания автоматически формирует протокол: транскрипт речи (русский, казахский и смешанная «шала-казах» речь), распознаёт говорящих, выделяет поручения с ответственным и сроком, собирает краткое саммари и экспортирует итоговый протокол в DOCX/PDF.

---

## 1. Название проекта

**«Хаттама AI»** (от каз. *хаттама* — протокол) — автоматическая система протоколирования совещаний с фиксацией и контролем поручений.

## 2. Краткое описание — проблема и для кого

Протоколы совещаний в организациях фиксируются вручную секретарями: это занимает время и создаёт риск потери или искажения поручений, сроков и ответственных лиц. Как следствие — снижается контроль исполнительской дисциплины.

**Решение** — локальный ИИ-ассистент, который:

- распознаёт речь участников (русский, казахский и «шала-казахский» — смешанная речь);
- различает говорящих и привязывает поручения к конкретному участнику;
- автоматически выделяет из транскрипта поручения (кто · что · к какому сроку);
- формирует итоговое саммари совещания;
- экспортирует протокол в файл (DOCX/PDF).

**Для кого:** секретари совещаний (освобождение от рутинной записи), руководители и кураторы поручений (прозрачность и контроль сроков), управленческие службы.

## 3. Что реализовано

- **Транскрибация речи (speech-to-text)** на русском, казахском и смешанной речи через локальную self-hosted модель `faster-whisper` (CTranslate2, CPU, без GPU). Сегменты помечаются языком `[ru]`/`[kk]`/смешанным.
- **Диаризация говорящих** (лёгкий режим, без GPU): сегменты Whisper → акустические признаки (F0, энергия, спектральные характеристики) → автоматическая кластеризация на «Говорящий 1…N».
- **Выделение поручений** на основе LLM: ответственный, суть задачи, срок, приоритет.
- **Нормализация сроков**: «к пятнице», «до конца недели», «через два дня» → конкретная дата.
- **Привязка поручения к говорящему**: ответственный сопоставляется с репликами диаризации (по имени в тексте реплик и контексту), выводятся «Говорящий → поручение».
- **Саммари совещания** — краткая выжимка решений и итогов.
- **Экспорт протокола** в текстовый протокол (транскрипт + таблица поручений + саммари) в **DOCX** и **PDF**.
- **Веб-интерфейс**: загрузка записи → прогресс-статусы по этапам → результат → экспорт.
- **Дашборд поручений** (SQLite): статусы «в работе / просрочено / выполнено» и история совещаний.
- **On-premise упаковка**: `setup.sh` + `run.sh`, передача аудио во внешние облачные сервисы не используется для распознавания речи.

## 4. Как работает решение — сценарий

1. **Вход:** пользователь загружает аудио/видеозапись совещания (MP3/WAV/MP4 и т.п.) в веб-интерфейс. Опционально — список участников.
2. **Транскрипция:** `faster-whisper` распознаёт речь с указанием таймингов и языка каждого сегмента (включая смешанную русско-казахскую речь).
3. **Диаризация:** сегменты речи группируются по говорящим — формируется размеченный по участникам транскрипт.
4. **Извлечение поручений:** LLM выделяет из размеченного транскрипта структурированные поручения (ответственный, суть, срок_raw); срок нормализуется до даты; ответственный сопоставляется с говорящим по имени в репликах.
5. **Саммари:** LLM формирует краткую выжимку совещания.
6. **Выход:** веб-страница с транскриптом по говорящим, саммари и таблицей поручений; кнопки экспорта в **DOCX/PDF**; данные сохраняются в SQLite для дашборда.

```
Аудио/видеозапись (MP3/WAV/MP4)
        │
        ▼
   TranscribeAgent (faster-whisper: текст + тайминги + [ru]/[kk])
        │
        ▼
   DiarizeAgent (акустические признаки → «Говорящий 1..N»)
        │
        ▼
   AlignAgent (сшивка транскрипта с репликами говорящих)
        │
        ▼
   ExtractAgent (LLM: поручения {ответственный, суть, срок, приоритет} + нормализация дат + привязка к говорящему)
        │
        ▼
   SummarizeAgent (LLM: краткое саммари)
        │
        ▼
   ExportAgent (протокол: транскрипт + поручения + саммари → DOCX/PDF + SQLite)
        │
        ▼
   Веб-интерфейс + дашборд поручений
```

## 5. Технологии

| Слой | Стек |
|---|---|
| Backend | Python 3, FastAPI, Uvicorn |
| Распознавание речи | `faster-whisper` (CTranslate2, модель Whisper `small`, CPU int8) — self-hosted |
| Анализ аудио | NumPy/SciPy (акустические признаки для диаризации), FFmpeg (конвертация) |
| LLM (извлечение/саммари) | OpenAI-совместимый клиент: OpenAI API (ключи организатора) **или** NVIDIA NIM; провайдер задаётся в `.env`. Офлайн-fallback — детерминированный извлекатель поручений по правилам. |
| Нормализация дат | Python `dateutil` + кастомные правила рус. выражений |
| Экспорт | `python-docx` (DOCX), `reportlab` (PDF) |
| Хранилище | SQLite (совещания, поручения, статусы) |
| Фронтенд | Статика (HTML/CSS/JS), прогресс по этапам, дашборд |
| Развёртывание | `scripts/setup.sh`, `scripts/run.sh` (локальный запуск без Docker) |

> Ключевое требование трека — «закрытый контур заказчика»: **распознавание речи выполняется локальной моделью**, аудио не передаётся в облако. Облачные LLM-ключи используются только для обработки уже полученного текста транскрипта и предоставлены организаторами; предусмотрен полностью офлайн-режим работы.

## 6. Архитектура проекта

```
hack-c998cc7c-ai-problem/
├── backend/
│   ├── main.py              # FastAPI-приложение, REST API, раздача фронтенда
│   ├── orchestrator.py      # агентный пайплайн: планирование этапов, статусы, обработка ошибок
│   ├── llm_client.py        # OpenAI-совместимый LLM-клиент (OpenAI / NVIDIA NIM / fallback)
│   ├── db.py                # SQLite: совещания, транскрипты, поручения, статусы
│   ├── date_parser.py       # нормализация сроков («к пятнице» → дата)
│   └── agents/
│       ├── transcribe.py    # faster-whisper: сегменты + язык + тайминги
│       ├── diarize.py       # VAD-признаки → кластеризация говорящих
│       ├── align.py         # сшивка транскрипта с говорящими
│       ├── extract.py       # LLM: поручения + привязка к ответственным
│       ├── summarize.py     # LLM: саммари
│       └── export.py        # DOCX/PDF, структурированный протокол
├── frontend/                # index.html, app.js, styles.css
├── samples/                 # демо-аудиозаписи совещаний (материалы трека)
├── scripts/
│   ├── setup.sh             # venv + зависимости + скачивание моделей + проверка ключей
│   └── run.sh               # запуск сервера
├── tests/                   # pytest: полный прогон пайплайна на демо-записи
├── data/                    # загруженные файлы и результаты (в .gitignore)
├── .env                     # ключи LLM (в .gitignore, НЕ коммитится)
└── README.md
```

**Агентный оркестратор:** пайплайн состоит из независимых агентов, каждый возвращает структурированный результат; оркестратор запускает этапы, валидирует выходы LLM по JSON-схеме, повторяет запрос при некорректном выводе и проксирует статусы в веб-интерфейс.

## 7. Установка и запуск

Требования: Linux с FFmpeg, Python 3.10+, интернет на этапе установки (скачивание моделей), ~6 ГБ свободного места.

```bash
# 1) клонировать репозиторий
git clone https://github.com/BAITC-Hacks/hack-c998cc7c-ai-problem.git
cd hack-c998cc7c-ai-problem

# 2) настроить ключи LLM (опционально; без них — офлайн-fallback)
cp .env.example .env
#   → вписать OPENAI_API_KEY или NVIDIA_NIM_API_KEY

# 3) установка: venv + зависимости + модели распознавания
bash scripts/setup.sh

# 4) запуск сервера
bash scripts/run.sh
# откройте http://localhost:8000
```

## 8. Как проверить решение (сценарий для жюри)

1. Открыть `http://localhost:8000`.
2. Нажать «Загрузить запись» и выбрать демо-файл из `samples/` (или свою аудиозапись совещания).
3. Наблюдать прогресс по этапам: транскрипция → диаризация → поручения → саммари.
4. Проверить результат:
   - транскрипт размечен по говорящим («Говорящий 1, Говорящий 2…») и по языку (`[ru]`, `[kk]`);
   - таблица поручений содержит: ответственный · суть · срок (в т.ч. нормализованную дату при наличии «к пятнице» и т.п.);
   - саммари отражает суть совещания.
5. Нажать «Экспорт DOCX» и «Экспорт PDF» — файлы протокола успешно создаются.
6. Перейти на вкладку «Дашборд» — совещание и поручения со статусами появились в списке.

Автоматическая проверка: `pytest` (пример того же сценария — см. `tests/`).

## 9. Данные и интеграции

- **Источники данных:** аудио/видеозаписи совещаний (MP3/WAV/MP4), загружаемые пользователем; демо-записи в `samples/` — материалы трека (синтетические/анонимизированные).
- **Внешние сервисы:**
  - распознавание речи — **локальная модель**, без передачи аудио в облако (требование трека);
  - LLM (OpenAI / NVIDIA NIM) — только текст транскрипта, ключи предоставлены организаторами; при отсутствии сети включается офлайн-fallback.
- **Хранилище:** SQLite (локально, без внешних СУБД).
- **Ключи:** в `.env` (не в репозитории).

## 10. Ограничения текущей версии

- Диаризация — **лёгкий режим** (без GPU): надёжно разделяет реплики по паузам и акустике, но на наложении голосов может ошибаться; обучение отпечатков голосов по тембру — в планах.
- Точность распознавания смешанной («шала-казах») речи зависит от модели Whisper; в конфиге можно поднять модель до `medium/large` (требует больше RAM).
- Встроенное подключение к Teams/Zoom/Meet как участник — вне текущего объёма (поддерживается загрузка записей и потоков) .
- Полноценная интеграция с СЭД, автоматическая рассылка выдержек и контроль исполнения через внешние системы — вне обязательной части (этапы развития).
- Офлайн-fallback-извлечение работает по правилам и уступает LLM на сложных формулировках сроков.

## 11. Deployed-версия

Локальный запуск (открытый контур трека): `http://localhost:8000`. Отдельный публичный деплой не выполняется — решение предназначено для **on-premise** размещения у заказчика.
